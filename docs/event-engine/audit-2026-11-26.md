# Audyt projektu pod Event Engine — 2026-11-26

## Aplikacja

- Next.js 15 (App Router), React 19, TypeScript strict, Supabase JS v2 + `@supabase/ssr`, MapLibre. Hosting Vercel (`event-map`, Node 24), domena mapaimprez.pl.
- Panel admina z guardem `requireAdmin` (rola w `profiles`), moderacja `pending_review` w `/admin/review`.
- CI GitHub Actions: lint, testy (vitest, sieć zablokowana), typecheck, build.

## Baza (z `database.types.ts`)

- Tabele domenowe: `events`, `locations`, `cities`, `categories`, `event_sources`, `organizers`, … oraz nieużywane dotąd `scraping_sources`, `raw_scraped_items`.
- Do zapisu wydarzeń wystarczą istniejące kolumny: `events.review_note` (marker), `event_sources.source_type/external_id/source_url` (pochodzenie i wycofanie). Nie znaleziono w repo ograniczeń CHECK na `event_sources.source_type`, ale **stan bazy wymaga potwierdzenia** (RLS/ograniczenia nie są w repo) — pierwszy zapis w trybie `pending_review` to zweryfikuje.
- `scraping_sources`/`raw_scraped_items` mają za mało pól na rejestr prawny, kolejkę i pamięć, a zapis surowego HTML do produkcyjnej bazy obciążałby plan Free — dlatego stan silnika jest w SQLite na VPS. **Migracja SQL nie jest potrzebna.**
- Plan Supabase Free (500 MB, 2 projekty w użyciu) — ryzyko pojemności przy dużym wolumenie (decyzja w `access-and-decisions.md`).

## Dotychczasowe pozyskiwanie treści

- `scripts/import-curated-events.mjs` — importer paczek JSON (≤50 wydarzeń), bezpieczna kolejność zapisu: `pending_review` → źródło → potwierdzenie → publikacja z warunkiem `updated_at`. Silnik używa tej samej kolejności i formuły klucza (`eventKey`).
- `docs/content-supply.md` — zasady legalności (bez hurtowego pobierania serwisów biletowych, bez obrazów bez praw, robots.txt, Nominatim ≤1 req/s, quirki stref czasowych Progresji, TAURON Areny, ERGO ARENY) — przeniesione do kodu (`legal/policy.ts`, `domain-quirks.json`).
- 36 paczek z 29.10–26.11.2026, ~600 wydarzeń z 181 domen; 183 strony główne trafiły do seedu silnika (bez domen biletowych), 142 z potwierdzoną lokalizacją obiektu, 12 z dominującą kategorią.
- Dotychczasowy proces wymagał włączonego komputera i sesji Codex — Event Engine to zastępuje.
- `importers/ebilet`, `scraping/*.json` (ignorowane przez git) — dane z serwisów biletowych/agregatorów; **silnik ich nie używa** (lista blokad L0).

## Infrastruktura

- Brak serwera poza Vercel/Supabase; brak Dockera na komputerze właściciela. Vercel nie nadaje się do długotrwałych crawlerów ⇒ potrzebny VPS (budżet w `budget.md`).
- Sekrety: `.env.local` (ignorowany) zawiera klucz serwisowy — na VPS trafia wyłącznie do `secrets/publisher.env`.
